## 3. Выполнение действия

### 3.1. Создание структуры решения .NET

Создано решение `OnlineStore.sln` и добавлены проекты:

- `OnlineStore.Contracts` — общие интерфейсы и DTO;
- `OnlineStore.Catalog` — модуль каталога товаров;
- `OnlineStore.Orders` — модуль заказов;
- `OnlineStore.Api` — точка входа (ApiHost);
- `OnlineStore.UnitTests` и `OnlineStore.IntegrationTests` — проекты тестов.

### 3.2. Фиксация контракта

В проекте `Contracts` создан интерфейс `IProductService`, который является границей взаимодействия между `OrderModule` и `CatalogModule`:

```csharp
public interface IProductService
{
    Task<ProductDto?> GetProductAsync(Guid productId, CancellationToken cancellationToken = default);
    Task<bool> CheckStockAsync(Guid productId, int quantity, CancellationToken cancellationToken = default);
}
```

### 3.3. Реализация модулей
- `CatalogModule`: Реализован `ProductService` с хранением данных в памяти и журналированием через `ILogger`.
- `OrderModule`: Реализован `OrderService`, который принимает `IProductService` через внедрение зависимостей (DI). При создании заказа модуль проверяет наличие товара и рассчитывает итоговую стоимость.

### 3.4. Интеграция в ApiHost
В `Program.cs` модули зарегистрированы через методы расширения (`AddCatalogModule`, `AddOrdersModule`). Настроены HTTP-эндпоинты `/api/products/{id}` и `/api/orders`.

### 3.5. Тестирование
- Модульные тесты: Проверка получения товара, проверки остатков (успешный и отрицательный сценарии), создание заказа.
- Интеграционные тесты: Проверка HTTP-запросов к API (успешное создание заказа и возврат 400 Bad Request при нехватке товара).

## 4. Схема потока данных: Создание заказа

```text
Клиент (HTTP)
   │ POST /api/orders { CustomerId, Items }
   ▼
ApiHost (Program.cs)
   │ вызывает OrderService.CreateOrderAsync()
   ▼
OrderModule
   │
   ├─ Для каждого товара в заказе:
   │     │
   │     ├─ вызывает IProductService.GetProductAsync() ──► CatalogModule (возвращает цену и имя)
   │     │
   │     └─ вызывает IProductService.CheckStockAsync() ──► CatalogModule (возвращает true/false)
   │
   ├─ Если CheckStockAsync == false:
   │     └─ Возвращает null (логирование предупреждения)
   │
   ─ Если все проверки пройдены:
         ├─ Рассчитывает TotalPrice
         ├─ Сохраняет заказ в памяти
         └─ Возвращает OrderDto
```         

## 5. Интеграционные проблемы и их устранение
В ходе интеграции модулей были выявлены и устранены следующие проблемы:

#### Проблема 1: Ошибки CS0234 и CS0246 в проектах Catalog и Orders

- Симптом: Компилятор не находил типы `IServiceCollection` и `ILogger<>`.
- Причина: Проекты были созданы как `classlib` и не имели ссылок на пакеты DI и логирования.
- Решение: Добавлены NuGet-пакеты `Microsoft.Extensions.DependencyInjection.Abstractions` и `Microsoft.Extensions.Logging.Abstractions` в проекты `Catalog` и `Orders`.

#### Проблема 2: Ошибка CS0246 в интеграционных тестах

- Симптом: Тесты не видели класс `OrderService`.
- Причина: Проект `UnitTests` не имел прямой ссылки на проект `Orders`.
- Решение: Добавлена ссылка на проект: dotnet add reference `src/OnlineStore.Orders/OnlineStore.Orders.csproj`.

#### Проблема 3: Ошибка CS0246 в Program.cs

- Симптом: `ApiHost` не видел интерфейсы и DTO из проекта `Contracts`.
- Причина: Отсутствовали директивы `using`.
- Решение: Добавлены using `OnlineStore.Contracts.Products`; и `using OnlineStore.Contracts.Orders`; в начало файла `Program.cs`.
