# Дефект BUG-002: Ошибка в проверке достаточности остатков на складе

## Симптом
Метод `CheckStockAsync` возвращает `false`, когда количество товара на складе **равно** запрошенному количеству, хотя должен возвращать `true`.

## Версия/коммит
Коммит: `chore: внесены изменения для отладки (этап 4)`

## Условия воспроизведения
1. Запустить тест `CheckStock_SufficientStock_ReturnsTrue`
2. Вызвать `CheckStockAsync` для товара с `StockQuantity = 10` и запросить `quantity = 5`
3. Ожидаемый результат: `true`
4. Фактический результат: `true` (тест проходит)

Но при запросе `quantity = 10` (равно остатку):
3. Ожидаемый результат: `true`
4. Фактический результат: `false` ❌

## Гипотезы
1. **Гипотеза А:** В условии проверки используется строгое неравенство `>` вместо `>=`.
2. **Гипотеза Б:** Поле `StockQuantity` в модели `Product` обновляется где-то ещё до вызова проверки.

## Инструмент диагностики
- Модульный тест `CheckStock_SufficientStock_ReturnsTrue` (xUnit)
- Точка останова в методе `ProductService.CheckStockAsync` на строке условия
- Логирование через `ILogger` (значения `product.StockQuantity` и `quantity`)
